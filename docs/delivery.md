# تحویل پیاده‌سازی محلی پنل ماکان

## تحویل جاری پس از نیازسنجی ۲۴ اکتبر

مرجع وضعیت جاری [گزارش پنل مالک](owner-panel-release.md) و [راهنمای استفاده](owner-panel-guide.md) است: همه بخش‌های پلتفرم در یک بسته Windows/Docker، ظاهر مشترک با الهام از بلوبانک، جست‌وجوی سراسری، انتخاب‌گرهای نام‌دار، راه‌اندازی مرحله‌ای سازمان، پیگیری رسید نامشخص و بررسی مستقل عضویت مدیر و اعتبار اشتراک. ۵۵ سیاست صریح قرارداد جدید در برنامه ثبت شده‌اند. جزئیات و اعداد بخش‌های بعدی، سابقه تحویل‌های قبلی هستند.

## اصلاح شماره همراه بر اساس درخواست کاربر

حساب‌های جاری روی API واقعی با شماره‌های `09100000000` تا `09100000005` آماده‌اند. ورود پنل فقط شماره همراه ۱۱ رقمی با شروع 09 می‌پذیرد؛ این قاعده در مرورگر و BFF اعمال شده است. گزارش‌های جاری `live-test-accounts.json` و `live-test-account-summary.json` مربوط به این شماره‌ها هستند؛ گزارش‌های شماره‌گذاری قبلی جداگانه با پسوند international-history بایگانی شده‌اند. بخش‌های بعدی سابقه مراحل قبلی هستند.

## حساب‌های واقعی و آزمون زنده پس از درخواست جدید کاربر

شش حساب روی سرور تست ساخته و آماده ورود شده‌اند؛ هر شش پروفایل کامل و فقط فضای Personal دارند. API مدیریت برای همگی 403 می‌دهد. نام، شماره و userId در `live-test-accounts.json` موجود است. با این حساب‌ها شش تست مرورگر واقعی پاس شد و پنل نشست مالک ایجاد نکرد. نتیجه تجمیعی در `live-test-account-summary.json` است: ۵۹ تست واحد، ۳۷ تست مرورگر شبیه‌سازی‌شده و ۶ تست زنده.

فرم ورود شماره بین‌المللی را می‌پذیرد. گزینه صریح و محدود به origin محلی برای آزمون OTP پیش از تعیین نقش مالک فعال شده است؛ کنترل ورود مالک همچنان بسته می‌ماند. حساب مالک یا نقش‌های مدرسه هنوز اعطا نشده‌اند و باید توسط نشست مالک موجود یا بک‌اند به شناسه‌های واقعی ایجادشده تخصیص یابند. قسمت‌های زیر سابقه تحویل قبل از ساخت این حساب‌ها هستند.

## آخرین تغییر ورود اختصاصی مالک در ۲ آبان ۱۴۰۵

ورود واقعی اکنون فقط برای نقش دقیق مالک پلتفرم همراه با `platform.access` است. OTP به‌تنهایی نشست محلی ایجاد نمی‌کند. کنترل در صفحات، API نشست و همه درخواست‌های BFF تکرار می‌شود و کنترل مجوز اختصاصی عملیات حفظ شده است. آدرس Backend به `http://94.184.32.84:8090` تغییر کرده است.

نام دقیق نقش مالک در PDF/OpenAPI وجود ندارد؛ `PLATFORM_OWNER_ROLE_KEYS=[]` عمداً ورود واقعی را می‌بندد. کلید نقش و شماره حساب مجاز برای پذیرش اتصال زنده لازم‌اند. راهنمای استفاده و گزارش PDF در `output/pdf` و شواهد آزمون در `owner-test-summary.json` هستند. ۴۸ تست واحد و هر ۳۷ تست مرورگر روی نسخه ساخته‌شده پاس شده‌اند. موارد زیر سابقه تحویل اولیه هستند و باید با این تغییر خوانده شوند.

## افزوده‌شده: مرور نمایشی بدون حساب

با درخواست بعدی کاربر، مسیرهای `/demo/admin` و `/demo/organization` اضافه شدند. داده‌های نمونه با برچسب دائمی مشخص‌اند و transport نمایشی در خود مرورگر پاسخ می‌دهد؛ هیچ تماس Backend یا ایجاد نشست واقعی انجام نمی‌شود. این حالت فقط خواندنی است، همه لینک‌های پنل در فضای `/demo` باقی می‌مانند و ورود واقعی همچنان جدا و محافظت‌شده است. این قابلیت جایگزین پذیرش اتصال زنده نشده است.

## نتیجه قابل بررسی

پروژه قابل اجرا در همین پوشه ساخته شده است. Next.js App Router، TypeScript strict، Tailwind، primitiveهای Radix، TanStack Query/Table، React Hook Form/Zod، Lucide و فونت Vazirmatn محلی استفاده شده‌اند. زبان ریشه فارسی و جهت RTL است؛ طراحی روشن و تیره و چیدمان دسکتاپ، تبلت و موبایل دارد.

فهرست و جزئیات سازمان، اعضا، دعوت و تغییر نقش، impact و تعلیق، provisioning، کاربران و نشست‌ها، read modelهای آموزش، نقش‌ها و انتساب، moderation و شواهد محدود پرونده، metadata پیام‌رسان، پلن/نسخه/انتشار، اشتراک/override، سفارش و پرداخت موجود، عملیات، Audit و حساب/MFA در رابط پیاده شده‌اند. مسیرهای دقیق و وضعیت هر صفحه در `ui-matrix.md` و Request/Response و پارامترها در `api-matrix.md` هستند.

Context مدیریت سازمان از پلتفرم جداست. داشبورد Manager، پرونده افراد، ویرایش نام‌های مجاز، دعوت اتصال حساب، روابط سرپرستی، کلاس، دوره و درس، انتساب معلم، ثبت‌نام، جلسه و الگوی برنامه، حضور و اصلاح مستند و گزارش‌های مدیریتی ساخته شده‌اند. محدودیت read model انتساب‌های قدیمی معلم و کاتالوگ دوره/درس در `backend-gaps.md` مشخص است.

## تصمیم‌های اصلی

tokenها فقط در سرور و ذخیره رمزگذاری‌شده هستند. cookie مرورگر صرفاً شناسه تصادفی HttpOnly است. درخواست‌های تغییردهنده Origin کنترل‌شده دارند. مقصد BFF ثابت و allowlist از قرارداد است؛ متن خصوصی پیام‌رسان خارج از آن است. permission از نام منو ساخته نشده؛ نگاشت رسمی تأییدنشده fail closed است. فرم و version از DTO واقعی می‌آیند؛ JSON بدنه DELETE حذف نشده و mutation کورکورانه retry نمی‌شود.

Context دارای revision سروری و قفل هر نشست است. Cache با حساب/revision جدا می‌شود، درخواست قدیمی لغو می‌شود و تب‌ها با BroadcastChannel مطلع می‌شوند. آرایه untyped فراگیر استفاده نشده و فهرست enrollment جایگزین نوع‌دار آن است. شمارش داشبورد از totalCount است و نمودار زمانی بی‌داده ساخته نشده است. واحد پول و maskedPhone همان داده سرور باقی می‌مانند.

## اتصال و آزمون

OpenAPI و چهار GET بدون ورود سرور واقعی بررسی شده‌اند. پذیرش عملیات دارای نشست واقعی هنوز انجام نشده است؛ کاربر اعلام کرده حساب آزمایشی را بعداً می‌سازد. پس از افزودن نسخه نمایشی، ۲۸ تست واحد و ۱۹ تست مرورگر مسیرهای واقعی با Backend آزمایشی به‌همراه ۵ تست demo بررسی شده‌اند؛ گزارش اجرای مجدد تست responsive در `testing.md` است. UI حالت عادی fallback ساختگی ندارد.

## موارد لازم برای بهره‌برداری واقعی

۱. ساخت حساب آزمایشی مجاز و آزمون OTP، Workspace و مجوزهای واقعی، بدون تغییر داده کاربران واقعی.

۲. دریافت نگاشت رسمی permission → Method/Path از Backend؛ ثبت در `PERMISSION_BINDINGS`. تا آن زمان اقدام‌ها و ناوبری تأییدنشده پلتفرم عمداً غیرفعال‌اند. این مورد، ادعای تکمیل اتصال زنده را محدود می‌کند.

۳. HTTPS بین مرورگر و Next.js و HTTPS یا شبکه امن تا Backend فعلی؛ تنظیم APP_ORIGIN و cookie Secure و ACL پوشه نشست.

۴. یک process Node با دیسک خصوصی پایدار برای این نسخه؛ چند replica به session store و قفل توزیع‌شده نیاز دارد. این مهاجرت در این تحویل انجام نشده است.

۵. رسیدگی به gapهای read model سازمانی و پذیرش providerها. AI/RAG، checkout واقعی، پذیرش واقعی Push و Runtime صوت/ویدئو غیرفعال مانده‌اند؛ صرف وجود API تأیید عملیاتی محسوب نشده است.
